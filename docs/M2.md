# Milestone M2 — Model Manager and hardware-aware recommendation

M2 turns the M1 hardware probe and model placeholder into an explicit production-model decision layer while keeping inference disabled until a production worker is actually implemented.

## Delivered

- Model Manager accessible without selecting an image.
- Native accelerator discovery:
  - Apple Silicon unified GPU / Metal capability;
  - NVIDIA GPU and VRAM through `nvidia-smi` when available;
  - CPU-only fallback when no supported accelerator is found.
- Curated catalogue entries for:
  - TripoSR;
  - Stable Fast 3D (SF3D);
  - TRELLIS.2 4B;
  - bundled Mock3D development adapter.
- Deterministic hardware assessments with user-visible reasons and caveats.
- Automatic recommendation restricted to permissively licensed, non-gated candidates that clear the safe hardware policy.
- Explicit user preference stored locally for the future M3 production adapter.
- Unit tests covering low-memory Apple Silicon, normal Apple Silicon, large-memory Apple Silicon, Linux/NVIDIA and unknown-hardware cases.
- M2 version bump to `0.2.0`.

## Compatibility policy

The policy is intentionally conservative and based on upstream published requirements rather than invented benchmark numbers.

### TripoSR

Upstream documents roughly 6 GB VRAM for its default single-image path and identifies the code and pretrained model as MIT licensed. Still2Solid therefore uses TripoSR as the default permissive candidate on ordinary supported hardware, but does not claim a certified MPS path until the M3 worker is validated.

On Apple Silicon, 16 GB or more unified memory is treated as a safe catalogue recommendation threshold. 8 GB is reported as memory constrained because the upstream ~6 GB model footprint must share unified memory with macOS and the application.

### Stable Fast 3D

The upstream project documents experimental Apple MPS support and recommends CPU execution when unified memory is below 32 GB. M2 reflects this directly instead of labelling sub-32-GB Apple systems as fully MPS-compatible.

SF3D is gated and uses the Stability AI Community License. It may be shown as hardware-compatible, but M2 never chooses it automatically because access and commercial-use terms require an explicit user decision.

### TRELLIS.2 4B

The upstream project currently documents Linux plus an NVIDIA GPU with at least 24 GB VRAM. M2 treats other operating systems as unsupported and sub-24-GB NVIDIA configurations as memory constrained. When the published threshold is met, TRELLIS.2 can outrank TripoSR as the automatic recommendation because the hardware is explicitly capable of the higher-end model.

## What M2 deliberately does not do

M2 does not:

- download any production model weights;
- accept gated-model terms;
- create Python/Conda environments;
- execute Hugging Face remote code;
- run TripoSR, SF3D or TRELLIS.2;
- expose a localhost inference server;
- claim benchmarked runtime or ETA for models that have not yet run locally.

Those are M3 concerns. M3 must pin revisions and hashes, implement checksum-verified installation, isolate model workers and prove inference on each enabled backend before the Generate button can switch away from Mock3D.

## Acceptance criteria

M2 is complete when:

1. M1 image selection, Mock3D generation, progress, cancellation, preview and mock export still work.
2. The Model Manager can be opened before or after image selection.
3. Hardware assessment never hides an unsafe model behind a generic “compatible” label.
4. Conditional/gated licences cannot be auto-selected.
5. Unknown browser-preview hardware produces no fake recommendation.
6. Recommendation tests, Svelte/TypeScript checks, UI build, Rust checks and Rust tests pass in CI.
