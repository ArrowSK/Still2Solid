# M7 — Release packaging

M7 makes the repository capable of producing normal desktop application bundles without requiring an end user to prepare Python manually.

## Delivered

- Tauri bundling is active.
- Canonical Still2Solid branding is wired to the web UI and native platform icon set.
- `package-lock.json` and `src-tauri/Cargo.lock` are committed for reproducible application builds.
- Python 3.12 standalone runtime artifacts are pinned per supported release target in `scripts/python-runtime.json` with SHA-256 hashes.
- `scripts/prepare_python_runtime.py` downloads, verifies and extracts the selected runtime into Tauri resources.
- Packaged model installers prefer the bundled interpreter; source builds may use an explicit/developer Python 3.11/3.12 fallback.
- The release workflow covers Apple-Silicon macOS, Windows x64 and Linux x64.
- macOS certificate/signing/notarization environment hooks are present.
- Version tags can create draft GitHub releases with generated Tauri artifacts.
- CI separately verifies that one pinned bundled runtime downloads, passes its checksum and runs as Python 3.12.

## Trust boundary

Bundling Python does not bundle third-party AI weights into the Git repository. Production models are still acquired by their reviewed installers, verified before activation and stored in application data rather than source control.

The packaged base interpreter and model-specific environments are separate. This keeps the application package deterministic while allowing model runtimes to remain independently installable/uninstallable.

## What M7 does not claim

M7 code completion is not proof that a public signed release already exists. Before publishing a normal-user build, the release workflow must be run with the intended signing credentials, the resulting artifacts must install on clean target machines and the release dependency/SBOM review must be completed.

The M1/8 GB Apple-Silicon benchmark is also separate physical validation. Packaging cannot prove model performance or memory safety on hardware that has not been measured.

## Acceptance boundary

M7 is complete in code when:

- packaged builds do not rely on a user's Python installation;
- Python artifacts are immutable and integrity-checked;
- application bundles are enabled and use correct native branding;
- release jobs exist for the intended desktop targets;
- signing/notarization hooks do not expose secrets in the repository;
- application/runtime data stay separated;
- CI can verify the bundled-runtime preparation path without downloading production model weights.
