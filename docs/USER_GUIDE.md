# User Guide

Still2Solid is designed around one primary path: **image → local 3D generation → preview → export**. Advanced controls exist, but you should not need them for a normal first run.

## 1. Choose an image

Drop an image onto the opening screen or choose a local file. JPEG, PNG, WebP and HEIC/HEIF are accepted by the UI when the platform can decode them.

The original image is not uploaded by Still2Solid.

Good source images usually have one clear object, a readable silhouette, limited occlusion and useful surface detail. A single photograph cannot reveal geometry that is completely hidden, so the back side and deeply occluded areas are necessarily inferred.

## 2. Review the Background check

After an image is selected, Still2Solid performs a tiny **local pixel check** around the image edges.

It does not call a cloud service and it does not run another large AI model. The check is deliberately lightweight:

- transparent edges usually mean the subject is already isolated;
- a coherent opaque border that differs from the centre is a strong sign of background;
- a busy opaque image is treated conservatively as potentially containing background.

You will see one of three messages:

### Background likely detected

Foreground isolation is recommended. Leave **Remove background** enabled unless you know the surrounding scene is part of the object you want reconstructed.

### The object already looks isolated

Transparent edges were found. Background removal is normally unnecessary, but you can still enable it if the image contains unwanted material inside the visible bounds.

### Background may be present

The quick heuristic is not confident. If the object sits on a desk, floor, wall, sofa, shelf, grass, sky or other surrounding scene, leaving background removal enabled is usually the safer choice.

The Background check is a suggestion, not a hard gate. Your selection is the setting used for generation and is also visible in Advanced mode as **Foreground isolation**.

## 3. Choose quality

Still2Solid exposes three product presets rather than a page of model-specific controls.

| Preset | Use it when | Trade-off |
| --- | --- | --- |
| **Fast** | You want the quickest preview or are on constrained hardware. | Lower extraction/texture pressure. |
| **Standard** | Normal use. | Balanced detail and memory use. |
| **Best** | You have enough memory/time and the image justifies more detail. | Highest memory/time pressure of the three presets. |

The presets do not promise a particular absolute quality level. Input quality and the limits of the selected model still matter.

## 4. Understand the active model

The top of the controls shows the **Active adapter**.

### TripoSR

This is the current production adapter. Still2Solid only activates it after the runtime is installed and verified and the model is selected by policy or explicitly by the user.

### Mock3D

Mock3D is a deterministic development fallback. It keeps the UI usable when no production model is ready. A Mock3D result is not a production reconstruction.

Open **Models** to see:

- detected hardware;
- memory/backend information;
- compatibility status;
- why a model has that status;
- licence notes;
- install/reinstall/uninstall actions where supported.

A warning such as **Memory constrained** is meaningful. Still2Solid intentionally avoids converting every technically launchable model into a green recommendation.

## 5. Generate

Press **Generate 3D locally** for TripoSR or **Generate Mock3D** when the fallback is active.

During production generation the app shows:

- the current stage;
- overall progress;
- cancellation;
- an ETA when enough comparable local history exists;
- ETA confidence.

On the first comparable run there may be no learned ETA. Still2Solid prefers saying that it is learning timing rather than showing a made-up countdown.

Cancelled and failed runs do not train the timing profile. Successful extreme outliers can be excluded from the median so one abnormal run does not permanently distort the estimate.

## 6. Preview the result

The result appears in the Three.js viewer.

- Drag to rotate.
- Scroll to zoom.
- Toggle **Wireframe** to inspect geometry.
- Toggle **Grid** for spatial reference.
- Use **Regenerate** if you want to try another quality/background/backend choice.

For production TripoSR output, the validated GLB is treated as the **canonical master**.

## 7. Export for normal 3D use

Open **Export…**.

### GLB — best fidelity

Downloads the exact validated GLB bytes generated by the production worker. This is the preferred master because materials and embedded textures remain together.

### OBJ package — compatibility

Creates a ZIP with:

- OBJ geometry;
- MTL material approximation;
- readable base-colour/normal PNG textures when available;
- an `asset.json` manifest explaining the conversion.

OBJ/MTL cannot represent the complete glTF PBR material model, so this is intentionally labelled as a compatibility export rather than an equivalent master.

### Raw STL — geometry only

Creates binary STL directly from the canonical geometry. Raw STL has no textures/colour and does not reliably encode units. Use **Prepare for print** when physical sizing matters.

## 8. Prepare for 3D printing

Open **Prepare for print…** instead of the normal export panel.

Still2Solid creates a separate in-memory print geometry. The GLB master stays unchanged.

### Set size

Choose the intended longest dimension in **millimetres**. This is explicit because one photograph does not contain trustworthy physical scale.

### Orient

Rotate around X, Y or Z in 90° steps. Print geometry uses printer-oriented Z-up coordinates and is placed on the build plate at Z=0.

### Flat base

The optional flat-base tool flattens only a shallow lowest band. It is intentionally conservative; it is not a general remesher or sculpting tool.

### Topology analysis

Still2Solid checks for important mesh problems, including:

- watertightness;
- boundary/open edges;
- non-manifold edges;
- non-manifold vertices;
- degenerate faces;
- winding conflicts;
- disconnected components/shells.

### Automatic repair

The repair pass can remove degenerates, make winding consistent, orient closed shells outward and cap simple planar holes when the case is safe enough.

It deliberately does **not** attempt aggressive remeshing, arbitrary large-hole reconstruction or invented geometry.

The result is labelled either:

- **Printable** — topology checks passed after preparation; or
- **Automatic repair incomplete** — unresolved topology remains and the file should be inspected in a dedicated mesh/slicer tool before printing.

“Printable” describes topology, not printability on every printer/material/orientation combination. Still2Solid does not generate supports, slicing profiles or G-code in M6.

### 3MF

Preferred print-prep export. The package explicitly states millimetres.

### Prepared STL

Coordinates are scaled to millimetres, but STL itself does not carry reliable unit metadata. Your slicer still needs to interpret those values as millimetres.

## 9. Advanced controls

Advanced mode currently exposes:

- backend selection: Auto, Metal/MPS, CUDA, CPU;
- the same foreground-isolation setting shown by Background check;
- detected platform/architecture;
- memory;
- preferred backend;
- accelerator;
- local timing profile details for TripoSR.

Use **Auto** unless you are troubleshooting or benchmarking a backend deliberately.

## 10. What stays local

Generation, preview, background analysis, learned timing and print preparation are local. The production runtime needs network access during installation because it downloads pinned source/model/runtime assets. Generation itself is designed to use the installed local runtime and blocks model downloads from the worker.

See [Security & Privacy](SECURITY_PRIVACY.md) for the exact boundary.

## 11. Storage and uninstall

Open **Settings → Storage** to see how much local space Still2Solid is using. The panel separates downloaded models, abandoned temporary work, cache and other application data.

- **Remove downloaded models** removes installed TripoSR and Stable Fast 3D runtimes/weights while keeping the application. Reinstall them later from **Models**.
- **Clear temporary files** removes Still2Solid cache plus abandoned generation workspaces and interrupted `.installing` model staging. Installed models and exported files are not touched.
- **Prepare for uninstall** removes installed model runtimes, Still2Solid app data, cache, abandoned temporary work and local `still2solid.*` preferences/timing data. Exported GLB/OBJ/STL/3MF files saved elsewhere are never deleted.

Still2Solid also performs automatic crash-recovery cleanup on startup. If the app was force-quit, crashed, or the computer lost power while a generation or model installation was in progress, the next launch removes leftover job workspaces and incomplete installer staging before a new worker starts.

Model installers do not use pip's shared user cache. Model-specific support caches required for offline inference stay under that model's Still2Solid-owned directory, so uninstalling the model removes those support files too.

macOS does not call an application when it is dragged to Trash, so Still2Solid cannot run complete-uninstall cleanup after deletion. For a complete uninstall, run **Prepare for uninstall** first, wait for **Cleanup complete**, quit Still2Solid, then move the application from **Applications** to **Trash**. On macOS the panel can open the Applications folder for the final step.

Replacing or updating the `.app` does **not** remove downloaded models. This is intentional so normal updates do not force large model downloads again.

## Limits worth remembering

Still2Solid cannot recover information a single image never contained. Packaged builds include the pinned Python runtime, while the current macOS download remains unsigned and may require one-time Gatekeeper approval. Safe automatic TripoSR recommendation on 8 GB Apple Silicon remains dependent on real-device measurement.
