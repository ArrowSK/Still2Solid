# Milestone M6 — Print preparation and 3MF

M6 turns the M5 geometry-export capability into an explicit, non-destructive print-preparation workflow.

## Delivered

- print-preparation UI alongside the existing M5 export UI;
- explicit target sizing by longest dimension in millimetres;
- deterministic Y-up → printer Z-up conversion;
- optional 90° X/Y/Z orientation controls;
- automatic build-plate placement at Z=0;
- optional flat-base band in millimetres;
- topology analysis for:
  - degenerate faces;
  - boundary/open edges;
  - non-manifold edges;
  - non-manifold vertex fans;
  - winding conflicts;
  - disconnected shells;
  - watertightness;
  - manifoldness;
  - closed-mesh volume;
- conservative repair for:
  - degenerate-face removal;
  - consistent face winding;
  - outward orientation of closed shells;
  - simple planar-hole capping;
- explicit `Printable` and `Automatic repair incomplete` outcomes;
- prepared geometry preview without changing the canonical GLB;
- 3MF Core export with explicit millimetre units;
- prepared binary STL export with explicit UI warning that STL itself does not encode units;
- unit tests for topology analysis, repair, scaling, 3MF package structure and binary STL layout;
- version bump to `0.6.0`.

## Physical scale policy

Single-image reconstruction does not establish trustworthy real-world dimensions. TripoSR produces reconstructed geometry, not a metrology result.

Still2Solid therefore does not infer centimetres or millimetres from the source photograph. Print preparation begins by asking for the desired longest dimension, defaulting to 100 mm. The geometry is scaled isotropically to that value.

This is a deliberate product-safety rule: a model that looks proportionally correct can still have completely arbitrary source coordinates.

## Coordinate policy

Three.js/glTF geometry is treated as Y-up for preview. Print outputs are Z-up.

The default print transform is:

`(x, y, z) -> (x, -z, y)`

This maps preview-up (`Y`) to printer-up (`Z`) while keeping a right-handed coordinate system. User X/Y/Z quarter-turns are then applied in print coordinates.

After scaling and orientation, the mesh is translated so the minimum Z coordinate is exactly 0 mm.

## Topology checks

M6 does not use a single vague “mesh healthy” flag. The analyser reports concrete topology conditions.

### Watertight

A mesh is considered watertight only when:

- every undirected edge has exactly two incident faces;
- there are no non-manifold edges;
- no degenerate faces remain.

### Manifold

Edge manifoldness is not sufficient for pinched vertices, so M6 also checks whether the incident faces around each vertex form a single connected fan.

The mesh is considered manifold only when both non-manifold edge and non-manifold vertex counts are zero.

### Winding

For every edge shared by two faces, the two faces should traverse that edge in opposite directions. Same-direction traversal is reported as a winding conflict.

### Components

Disconnected shells are counted and shown to the user. Multiple watertight shells are not automatically considered invalid because some printable objects legitimately contain several separate parts in one file, but a warning is shown.

## Conservative repair policy

M6 intentionally avoids aggressive remeshing.

### Allowed automatic changes

1. Degenerate triangles may be removed.
2. Face orientation may be propagated across shared two-face edges to make winding consistent.
3. Closed connected shells may be flipped as a whole when signed volume indicates inward orientation.
4. Simple closed boundary loops may be capped only when sufficiently planar and small relative to the target model size.
5. A planar loop lying on the explicitly requested flat-base plane may be capped even when larger, because the user explicitly asked for that base operation.

### Not attempted automatically

- arbitrary large-hole reconstruction;
- voxel remeshing;
- boolean union of disconnected shells;
- reconstruction of missing photographed geometry;
- wall-thickness generation;
- hollowing;
- support generation;
- slicing or G-code generation.

If repair cannot establish the required topology, the UI displays `Automatic repair incomplete` rather than hiding the failure. Export remains available so the user can continue in a dedicated mesh editor or slicer.

## Flat base

The flat-base option is expressed as a depth in millimetres and defaults to 0/off.

For a non-zero value, vertices in the lowest band are clamped to one plane. The operation is applied only to the prepared copy. Degenerate triangles caused by clamping are then removed, and a resulting planar base loop may be capped by the conservative hole-capping rules.

This is intentionally not described as a general-purpose boolean plane cut.

## 3MF

The prepared 3MF package is created locally and declares `unit="millimeter"` in the 3MF Core model.

M6 generates the minimum required OPC package structure:

- `[Content_Types].xml`
- `_rels/.rels`
- `3D/3dmodel.model`

The package contains geometry only. Material/texture transfer to printable 3MF is outside M6 because the first print-preparation goal is reliable dimensions and topology rather than colour 3D printing.

The ZIP container is produced with the already-used MIT-licensed `fflate` dependency, so M6 introduces no new third-party runtime dependency.

## Prepared STL

Prepared STL uses the same millimetre-scaled, Z-up, repaired geometry as the 3MF output.

STL itself carries no unit declaration. The filename and UI therefore state that the coordinates were prepared in millimetres and instruct the user to confirm millimetres in the receiving slicer.

The original M5 raw STL export remains available separately and is not silently changed into the prepared version.

## Non-destructive guarantee

M6 never overwrites or rewrites the canonical GLB. Print preparation loads its geometry into a separate in-memory representation. Closing the print-preparation panel returns the viewer to the canonical model.

## Acceptance criteria

M6 is complete when:

1. M1–M5 generation, Model Manager, local runtime, cancellation, learned ETA, preview and raw exports continue to work.
2. The user can specify final print size explicitly in millimetres.
3. The prepared preview uses the chosen size/orientation/base settings without modifying the GLB master.
4. Watertight, manifold, degeneracy, winding and disconnected-shell results are visible rather than hidden.
5. Conservative repair never claims success when open/non-manifold topology remains.
6. 3MF declares millimetre units explicitly.
7. Prepared STL is clearly distinguished from the raw STL and warns about STL unit ambiguity.
8. Print-preparation tests, existing UI tests/build, Python worker validation, Rust check and Rust tests pass in CI.
